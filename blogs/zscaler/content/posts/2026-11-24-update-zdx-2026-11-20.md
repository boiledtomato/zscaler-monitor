11月13日〜19日に公開された ZDX（Zscaler Digital Experience）の変更は**1件**でした。**定義済みアプリ（Predefined Applications）**に、**12件のアプリ**が加わっています。
目を引くのは、**ChatGPT、Claude、Gemini、Microsoft Copilot** といった**生成AI**のアプリです。業務で生成AIを使う組織が増えるなか、「AIが遅い」「つながらない」という問い合わせを、ほかの SaaS と同じように数字で調べられるようになります。

## どんな機能か：定義済みアプリとプローブ

ZDX は、利用者の端末から、業務で使うアプリまでの**体感品質**を測るサービスです（11月11日の記事で紹介）。測定は**プローブ**という仕組みで行います。

公式ドキュメント「About Applications」によると、ZDX のアプリには2種類のプローブが関わります。

- **Web プローブ**：アプリの URL に定期的にアクセスし、応答の速さなどを測る
- **Cloud Path プローブ**：端末からアプリまでの**ネットワークの経路**をたどり、どこで遅れているかを測る

**定義済みアプリ**は、Zscaler が用意している SaaS アプリの設定のひな形です。公式ドキュメントによると、定義済みアプリには**あらかじめ Web プローブと Cloud Path プローブが設定**されていて、**登録すると自動で有効**になります。自分で URL やプローブを一から設定する**カスタムアプリ**に比べて、手早く監視を始められます。

### ZDX で監視できるアプリの種類

公式ドキュメント「About Applications」をもとに、ZDX で設定できるアプリの種類を整理しておきます。

| 種類 | 内容 | プローブの設定 |
|---|---|---|
| 定義済みアプリ | Zscaler が用意した SaaS アプリのひな形。今回12件が追加 | Web・Cloud Path プローブが用意済み。登録すると自動で有効 |
| カスタムアプリ | 自社で URL を指定して作る SaaS・Web アプリ | Web プローブを自分で作る必要がある。多くは Cloud Path プローブも作る |
| ネットワークアプリ | 経路（Cloud Path）だけを監視するアプリ | Cloud Path プローブ1つだけで監視できる |
| 通話品質（UCaaS） | Microsoft Teams、Webex、Zoom の通話品質 | 先にテナントの登録（オンボード）が必要 |

通話品質の監視は、Microsoft 365 サブスクリプションと Advanced サブスクリプションで使えますが、Microsoft 365 サブスクリプションで使えるのは現在 **Microsoft Teams の通話品質だけ**です。
また Microsoft Teams では、アプリの URL（teams.microsoft.com）に加えて、音声や映像を中継するサービス（world.tr.teams.microsoft.com）への Cloud Path も自動で作られます。

今回の追加で、Google Meet が定義済みアプリになりました。ただし、これは**アプリとしての監視**で、Teams・Webex・Zoom のような**通話品質の監視**の対象に Google Meet が加わったという記載はありません。混同しないよう注意しましょう。

## 対象となる人・設定

- **ZDX を使っている**組織で、追加されたアプリ（とくに生成AIや Google のアプリ、Slack）の体感品質を監視したい組織
- これまで、これらのアプリを**カスタムアプリ**として自分で登録していた組織（定義済みアプリへの切り替えを検討できる）

ただし公式ドキュメントによると、使える定義済みアプリは **ZDX のサブスクリプション**（Standard、Microsoft 365、Advanced、Advanced Plus）によって異なります。今回の12件がどのサブスクリプションで使えるかは、原文に記載がありません。

## 運用者がやること

- [ ] Predefined Apps Collection で、追加された12件が自社のテナントに表示されているか確認する
- [ ] 業務でよく使っているアプリ（生成AI、Google のアプリ、Slack など）を登録する
- [ ] テナント ID が必要なアプリは、自社のテナントに合わせてパスを設定する（公式の推奨）
- [ ] すでにカスタムアプリとして同じアプリを登録している場合、二重に測らないよう、どちらを使うか決める
- [ ] 登録後、アプリのステータスが「Pending Onboard」のままになっていないか確認する

## 生成AIを測る意味

生成AIのアプリは、回答の生成に時間がかかるため、「遅い」と感じたときに、**AI側の処理が遅いのか、ネットワークの経路が遅いのか**を見分けにくいアプリです。
ZDX の Cloud Path プローブで経路を、Web プローブでアプリの応答を測っておけば、たとえば次のような切り分けがしやすくなります（個人の整理です）。

- 全員が同じように遅い → アプリ側やサービス全体の問題の可能性
- 特定の拠点やデータセンター経由の利用者だけが遅い → 経路の問題の可能性
- 特定の利用者だけが遅い → 端末や自宅のネットワークの問題の可能性

なお、プローブが測るのはアプリへの**接続と応答**です。AIが回答を作るのにかかる時間そのものを測るものではない点には注意が必要です（プローブの細かな仕様は公式情報で要確認）。
