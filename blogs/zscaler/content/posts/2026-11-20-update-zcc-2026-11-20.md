11月13日〜19日に公開された Zscaler Client Connector（ZCC）の更新は、**iOS 版の2件だけ**でした。件数は少ないものの、1件目の 5.0.1 は、**ZPA・ZIA に接続できなくなる不具合**の修正です。
先週の記事で紹介した iOS 版 5.0 の一般提供のあと、Zscaler Trust に既知の問題（Advisory）が出ていました。どの設定の組織が影響を受け、何をすればよいのかを整理します。

## iOS 5.0.1：Ownership ポスチャの判定失敗を修正

### 何が変わったか

5.0.1 は、**iOS 版 5.0.0 にモダンな新しい UI で上げたあと、ログインや再認証のときに Ownership ポスチャの判定が失敗する**問題を修正しました。リリースノートは、詳細を Zscaler Trust の記事（posts/32666）で確認するよう案内しています。

### どんな機能か

**デバイスポスチャ**とは、端末の状態（会社の端末か、証明書が入っているか、など）を確かめ、その結果をアクセスの条件に使う仕組みです。**Ownership（所有者）ポスチャ**は、その端末が組織の持ち物かどうかを判定する種類の一つで、「会社の端末からだけ社内アプリを使わせる」といったポリシーに使われます。

Trust の記事によると、判定が失敗した iOS 端末は次の状態になりました。

- このポスチャを条件にした **ZPA のアクセスポリシー**で、社内アプリに接続できない
- このポスチャを条件にした **ZIA のアクセスポリシー**で、インターネットの宛先に接続できない
- ZPA・ZIA・ZDX の**利用資格（エンタイトルメント）**の判定も失敗する

影響を受けたのは、次の**すべて**に当てはまる iOS 端末です。

- Client Connector を **4.5.1 から 5.0.0 にアップグレード**した
- **Modern Experience UI**（新しい画面デザイン）を使っている
- **Ownership ポスチャ**を、利用資格や ZPA・ZIA のアクセスポリシーの条件に使っている

逆に、5.0.0 を新しくインストールした端末、Classic UI のまま使っている端末、Ownership ポスチャを条件にしたポリシーがない組織は、影響を受けません。

なお Zscaler は、影響を減らすため、Ownership ポスチャを設定しているテナントでは、iOS で Modern UI を既定で使う設定を**無効にした**としています。

### 運用者がやること

- [ ] Ownership ポスチャを ZPA・ZIA のポリシーや利用資格に使っているか確認する
- [ ] iOS 端末の Client Connector を **5.0.1 以降**（今週出た 5.0.2 を推奨）に更新する。App Store での配信は11月13日から
- [ ] 暫定策として「Default to Modern Client UI Experience」を無効にしていた場合、**影響を受ける端末がすべて 5.0.1 以降になってから**、有効に戻す（Infrastructure > Client Connector > App Profile & Platform Settings > iOS > Platform Settings）
- [ ] 設定変更を急いで反映したい端末は、アプリ右上の設定から Application Info を開き、App Policy の **Update** を押す（通常は80分ごとに自動取得）

Trust の記事は11月19日付で「5.0.1 以降で解決済み」と更新されています。

## iOS 5.0.2：ZPA の検索ドメインと TCP タイムアウトの修正

5.0.2 では、次の2つの問題が修正されました。

### ZPA の検索ドメインが DNS 設定に反映されない

**何が変わったか**：ZPA（Private Access）の**検索ドメイン**が、ZPA の DNS 設定に反映されない問題が直りました。

**どんな機能か**：検索ドメインは、「intranet」のような短いホスト名に、「example.co.jp」のような組織のドメインを自動で補って名前解決する仕組みです。先週の記事で紹介したとおり、iOS 版 5.0 では、この自動補完が**既定で無効**（VPN プロファイルの MatchDomainsNoSearch が既定で 1）になりました。

**対象となる人・設定**：ZPA の検索ドメインを設定し、iOS 端末から短いホスト名で社内アプリにアクセスしている組織。MatchDomainsNoSearch を 0 に戻して自動補完を使っている場合も、この修正が前提になると考えられます（両者の関係は公式情報で要確認）。

**運用者がやること**：5.0.2 へ更新したうえで、短いホスト名での社内アプリへのアクセスを確認します。

### データのない TCP 接続が20秒でタイムアウトする

**何が変わったか**：データのやり取りがない TCP 接続が、**20秒でタイムアウト**してしまう問題が直りました。

**どんな機能か**：チャットや業務アプリの一部は、接続を開いたまま、しばらく何も送らずに待つことがあります。こうした接続が20秒で切れると、アプリの再接続が増えたり、通知が届かなかったりする可能性があります（影響の具体例は原文に記載なし）。

**対象となる人・設定**：原文に条件の記載はありません。5.0 系を使っている iOS 端末で、アプリの接続がたびたび切れるという問い合わせがあれば、この問題を疑えます。

**運用者がやること**：5.0.2 へ更新します。

## 今回の件から学べること

今回の不具合は、「**アップグレードした端末**」「**新しい UI**」「**特定のポスチャを使うポリシー**」という3つの条件が重なったときだけ起きました。新規インストールでの検証だけでは見つけにくい種類の問題です。メジャーバージョン（4.x → 5.0 など）を全社に配る前に、次の点を確認しておくと安心です（個人の運用上の提案です）。

- **アップグレードでも試す**：検証端末は、新規インストールだけでなく、今の本番と同じバージョンから上げた端末も用意する
- **ポリシーの条件ごとに試す**：ポスチャ（Ownership、証明書、MDM 管理など）を条件にしたポリシーの対象ユーザーで、ZPA・ZIA の両方にアクセスできるか確かめる
- **ログイン・再認証も試す**：アップグレード直後だけでなく、ログインし直したときや、再認証が求められたときの動きも見る
- **Trust の Advisory を見る**：リリースノートだけでなく、Zscaler Trust の既知の問題（Advisory）にも目を通す。今回も、5.0.1 のリリースノートから Trust の記事へ案内があった

## まとめ

- 今週は iOS 版の 5.0.1・5.0.2 のみ。5.0.1 は、Ownership ポスチャを使う組織で ZPA・ZIA に接続できなくなる不具合の修正で、重要度が高い
- 暫定策で Modern UI の既定を無効にしていた組織は、すべての端末を 5.0.1 以降にしてから有効に戻す
- 5.0.2 は ZPA の検索ドメインと TCP の20秒タイムアウトを修正。iOS 端末は 5.0.2 への更新がおすすめ

明日（土曜）は、同じ期間の **ZIA** のアップデートを取り上げます。
