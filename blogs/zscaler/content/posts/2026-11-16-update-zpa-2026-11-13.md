Zscaler の製品別アップデート、今週の3本目は **ZPA（Zscaler Private Access）** です。
11月6日〜12日にデプロイされた ZPA の変更は4件で、最大のポイントは、社内のワークフローから **API で一時的にアクセスを渡す「Entitlement Orchestration」** の一般提供です。委託先の受け入れや緊急時の特権アクセスを、ポリシーを書き換えずに自動化できるようになります。

## 今週の変更

| 変更 | 区分 | デプロイ日 | 対象となる人・設定 | 重要度 |
|---|---|---|---|---|
| <span data-env="zpa authsvc"></span>Entitlement Orchestration（API による一時的なアクセス付与） | 一般提供 | 11/12 | Authentication Service のローカルユーザーグループを使う ZPA の組織 | 高 |
| <span data-env="zpa"></span>Manager ソフトウェア 26.59.1（推奨更新） | 一般提供 | 11/9 | App Connector・Private Service Edge などを RHEL で動かしている組織 | 中 |
| <span data-env="zpa windows legacyvpn"></span>Network Segment のワイルドカード対応 | 限定提供 | 11/9 | VPN（for Legacy Apps）を Windows の Client Connector 5.0 以降で使う組織 | 中 |
| <span data-env="zpa isolation"></span>ブラウザ分離の利用者向け機能の強化 | 限定提供 | 11/6 | ZPA のアプリでブラウザ分離を使う組織 | 低 |

## Entitlement Orchestration：必要なときだけアクセスを渡す

### 何が変わったか

ZPA で **Entitlement Orchestration** が使えるようになりました。社内のワークフロー（申請・承認の仕組みなど）が ZPA の API を呼び出し、**Authentication Service のローカルユーザーグループに利用者を追加・削除する**ことで、社内アプリへのアクセスを**必要なときだけ（Just-in-Time、JIT）**付けたり外したりできます。

### どんな機能か

これまで、委託先に一時的にアクセスを渡すには、アクセスポリシーやグループの設定を管理者が手で変え、期限が来たら手で戻す必要がありました。戻し忘れれば、不要なアクセスが残ります。
Entitlement Orchestration では、**アクセスポリシーとアプリケーションセグメントは最初に一度だけ設定**しておき、あとは**グループの所属だけ**を API で変えます。

公式ドキュメントによると、流れは次のとおりです。

1. 利用者が、組織の社内ワークフローやツールで、社内アプリへのアクセスを申請する
2. 社内のワークフローが API を呼び、そのアプリに対応するローカルユーザーグループに利用者を追加する
3. ZPA が、更新されたグループの所属を、事前に設定したアクセスポリシーで評価する
4. グループの所属や端末のポスチャなど、ポリシーの条件をすべて満たせば、アクセスを許可する
5. 期限が来たり取り消されたりしたら、ワークフローが API で利用者をグループから外す
6. ZPA がグループの所属を評価し直し、アプリへのアクセスを終了する

### どんな場面で使うか

公式ドキュメントは、次のような使い方を挙げています。

| 場面 | 内容 |
|---|---|
| 委託先・外部の人の受け入れ | チケットや人事の手続きと連動して、アクセスを自動で付け外しする |
| 緊急時の特権アクセス（ブレークグラス） | 障害対応などで一時的に強い権限を渡し、終わったらすぐ取り消す |
| プロジェクト単位のアクセス | 担当している期間だけアクセスを許可する |
| 申請・承認型のアクセス | 管理者が承認・却下したときに、API でグループの追加・削除を実行する |
| 時間帯を限ったアクセス | 業務時間だけアクセスを許可し、時間外はセッションを終了する |

### 対象となる人・設定

- ZPA を使い、ユーザーの管理に **Authentication Service のローカルユーザーグループ**を使える組織
- API を呼び出せる社内のワークフロー（申請システム、チケットシステムなど）を用意できる組織

### 運用者がやること

- [ ] 一時的なアクセスを手作業で付け外ししている業務（委託先、緊急対応など）を洗い出す
- [ ] 対象アプリのアプリケーションセグメントと、対応するローカルユーザーグループ・アクセスポリシーを設計する
- [ ] 社内のワークフローから API を呼ぶ権限と、付与・取り消しの記録の残し方を決める

## Manager ソフトウェア 26.59.1（推奨更新）

### 何が変わったか

App Connector・Private Service Edge・Private Cloud Controller・Network Connector の **Manager ソフトウェア 26.59.1** が、推奨更新として公開されました。App Connector と Private Service Edge は Red Hat Enterprise Linux（RHEL）8.x・9.x 向け、Private Cloud Controller と Network Connector は RHEL 9.x 向けの RPM パッケージが更新されています。

### どんな機能か

公式ドキュメントによると、ZPA の各コンポーネントは2層のソフトウェアで動いています。

- **Manager**（App Connector なら `zpa-connector`）：子のソフトウェアを監督・制御し、更新を可能にする
- **子のソフトウェア**（`zpa-connector-child` など）：マイクロトンネルを張り、社内アプリと実際に通信する

Manager は、ソフトウェアのダウンロードに OS の信頼済み CA バンドルを使う、と公式ドキュメントに書かれています。

### 対象となる人・設定

App Connector・Private Service Edge などを、RHEL のサーバーに RPM パッケージで導入している組織です。

### 運用者がやること

- [ ] 自社のコンポーネントの Manager のバージョンと、OS（RHEL 8.x／9.x）を確認する
- [ ] 公式の「Manager Upgrades」の手順に沿って、更新の時期を決める
- [ ] OS の CA バンドルが最新か確認する（Manager のダウンロードに使われるため）

## VPN（for Legacy Apps）：Network Segment のワイルドカード対応

### 何が変わったか

VPN（for Legacy Apps）の **Network Segment** を、`*.domain.com` のような**ワイルドカード**で定義できるようになりました。FQDN（完全なドメイン名）が多い環境で、設定を簡単にできます。区分は**限定提供**で、**Windows の Client Connector 5.0 以降**だけで使えます。

### どんな機能か

VPN（for Legacy Apps）は、その名前のとおり、従来型（レガシー）のアプリ向けにネットワーク単位で接続する機能と位置づけられています（対象となるアプリの条件は公式情報で要確認）。Network Segment では、利用者がアクセスする先を IP アドレス（またはサブネット）か FQDN で指定し、FQDN の場合は名前解決に使う DNS サーバーも指定します。公式ドキュメントでは、ワイルドカード `*` で、特定のドメインのすべてのサブドメインを含められると説明されています。

### 運用者がやること

- [ ] VPN（for Legacy Apps）で、同じドメインのサブドメインを1件ずつ登録していないか確認する
- [ ] ワイルドカードを使う場合、対象の利用者が Windows の Client Connector 5.0 以降か確認する

## ブラウザ分離の利用者向け機能の強化

ZPA でも、ブラウザ分離の Zero Trust Mode メニューに、クリップボード・翻訳・ページ内検索・トラブルシュートの機能が加わりました（限定提供）。内容は、11月14日の ZIA の記事で詳しく解説したものと同じです。ZPA では、社内アプリを分離して見せるときに使われます。

## まとめ

- **Entitlement Orchestration** で、ポリシーを書き換えずに、API でグループの所属を変えるだけで一時的なアクセスを付け外しできるようになった
- App Connector などの **Manager ソフトウェア 26.59.1** が推奨更新。RHEL での運用環境を確認して更新を計画する
- VPN（for Legacy Apps）の Network Segment がワイルドカードに対応（限定提供、Windows の Client Connector 5.0 以降）
