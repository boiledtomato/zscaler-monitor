2026年11月17日、Oracle の **Java SE** と **GraalVM** に含まれるコンパイラ部品に、深刻度 **HIGH（CVSS 8.1）** の脆弱性 **CVE-2026-114938** が公表されました。
Java は業務システムやサーバーで広く使われているため、Zscaler も同日 Trust ポータルにアドバイザリを出し、**自社クラウドへの影響を調査中**としたうえで、利用者に **OpenJDK の更新**を推奨しています。
ここでは、NVD（米国の脆弱性データベース）と Zscaler の公表内容をもとに、脆弱性の中身と、利用者が今やることを整理します。

> この記事は 11/18 時点の情報です。Zscaler の見解は **「調査中」** で、影響の有無はまだ確定していません。最新情報は Zscaler Trust のアドバイザリを確認してください。

## 概要

| 項目 | 内容 |
|---|---|
| CVE 番号 | CVE-2026-114938 |
| 対象ソフトウェア | Oracle Java SE、Oracle GraalVM for JDK、Oracle GraalVM Enterprise Edition（コンパイラ部品） |
| 深刻度 | CVSS 3.1：8.1（HIGH） |
| 弱点の種類 | CWE-122（ヒープ領域のバッファオーバーフロー） |
| 公開日 | 2026-11-17（NVD・Zscaler Trust） |
| Zscaler の見解 | **調査中**（Under Investigation）。全クラウド向けのアドバイザリ |
| 利用者の対応 | **要**：自分で管理する OpenJDK を提供元の最新版へ更新（Zscaler の推奨） |

## どんな脆弱性か（原因）

NVD によると、脆弱性があるのは Java SE と GraalVM の**コンパイラ（Compiler）部品**です。弱点の種類は **CWE-122（ヒープ領域のバッファオーバーフロー）** に分類されています。
ヒープ領域のバッファオーバーフローとは、プログラムが実行中に確保したメモリ（ヒープ）の決められた範囲を超えてデータを書き込んでしまう欠陥のことです（一般的な説明）。うまく悪用されると、周りのデータを壊したり、攻撃者が用意した処理を動かされたりするおそれがあります。

NVD の説明で重要なのは次の点です。

- **攻撃は難しい**（Difficult to exploit）が、**認証なし**で、**ネットワーク経由**（複数のプロトコル）で狙える
- 成功すると、Java SE などが**乗っ取られる**（takeover）おそれがある
- 主な入口は、**Web サービスなどを通じて、外から受け取ったデータを該当部品の API に渡す**場面
- 信頼できない Java Web Start アプリやアプレットのような、サンドボックスで動くコードからの悪用ではない

認証も利用者の操作もいらず、成功すれば被害は大きい一方で、**攻撃の複雑さが「高」**と評価されているため、基本値は 8.1 にとどまっています。「すぐに誰でも悪用できる」種類ではありませんが、外部からデータを受け取る Java のサービスを運用しているなら、早めに更新したい脆弱性です。

| 製品 | バージョン |
|---|---|
| Oracle Java SE | 8u511b33-perf、17.0.21.0.3、21.0.13.0.3、25.0.5.0.3、27.0.1.0.3 |
| Oracle GraalVM for JDK | 17.0.21.0.3、21.0.13.0.3 |
| Oracle GraalVM Enterprise Edition | 21.3.20.0.3 |

修正版の詳細は、Oracle の 2026年11月のセキュリティアラート（Critical Patch Update）で確認してください。OpenJDK のディストリビューション（各社が配布する OpenJDK）を使っている場合は、それぞれの提供元の情報を確認します。

## Zscaler のクラウドへの影響

Zscaler Trust のアドバイザリ（11/17 公開、全クラウド向け）の内容は次のとおりです。

- Zscaler のセキュリティとエンジニアリングのチームが、CVE-2026-114938 と**関連する依存関係（downstream dependencies）**の影響を**調査中**
- 利用者には、影響を受ける **OpenJDK を、提供元が出している最新版に更新する**ことを推奨

つまり 11/18 時点では、ZIA・ZPA などの Zscaler のクラウドに影響があるかどうかは**まだ公表されていません**。「影響なし」と決めつけず、続報を待つ段階です。

Zscaler のアドバイザリは、特定の Zscaler 製品（App Connector、Private Service Edge、Branch Connector、Cloud Connector など）に OpenJDK が含まれるかどうかには触れていません。そのため、ここでは**利用者が OS を管理しているサーバー全般**を対象に、確認の手順を挙げます。

**確認すること**

- [ ] 社内のサーバー・仮想マシンで、Java（Oracle Java SE、OpenJDK、GraalVM）が入っているものを洗い出す
- [ ] App Connector や Private Service Edge を置いている仮想マシンに、別の用途で Java を入れていないか確認する
- [ ] 入っている Java のバージョンが、上の「影響を受けるバージョン」に当てはまるか確認する
- [ ] とくに、外部からデータを受け取る Web サービスや API サーバーを優先して、提供元の最新版へ更新する
- [ ] 更新後、アプリケーションが正常に動くか確認する
- [ ] Zscaler Trust のアドバイザリ（posts/32751）の続報を確認する

### ZPA を使っている場合の考え方

ZPA を使って社内アプリを公開している場合、利用者はインターネットに直接さらさずに社内アプリへ接続できます（11月6日の ZPA の記事参照）。ただし、ZPA 経由で接続できる利用者からはアプリに届くため、**社内アプリ自体の Java の更新が不要になるわけではありません**。アクセスできる利用者を絞ったうえで、更新を進めましょう。

## まとめ

- CVE-2026-114938 は Java SE・GraalVM のコンパイラ部品の脆弱性（CVSS 8.1、HIGH）。攻撃は難しいが、認証なし・ネットワーク経由で乗っ取られるおそれがある
- Zscaler は 11/17 時点で自社クラウドへの影響を**調査中**。断定的な情報はまだない
- 利用者は、自分で管理するサーバーの Java（OpenJDK など）を洗い出し、外部からデータを受け取るものから最新版へ更新する
