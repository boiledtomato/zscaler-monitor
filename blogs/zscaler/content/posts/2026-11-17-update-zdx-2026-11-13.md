Zscaler の製品別アップデート、今週の4本目（最終回）は **ZDX（Zscaler Digital Experience）** です。
11月6日〜12日の ZDX の変更は、Client Connector に組み込まれて端末上で測定を行う **ZDX モジュール**の2件でした。
Windows 版では **32bit（x86）版 Windows のサポート終了**という、端末の棚卸しが必要な変更が入っています。iOS 版では、バッテリーへの影響を抑える改善が入りました。

## Windows 版 ZDX モジュール 4.9.0.51

### 32bit（x86）版 Windows のサポート終了

**何が変わったか**
Client Connector 5.0 のリリースに合わせて、**32bit（x86）版の Windows クライアント**のサポートが終了しました。

**対象となる人・設定**
32bit 版の Windows で、Client Connector と ZDX を使っている組織です。工場の制御用端末や、更新されずに残っている古い PC などが該当しやすいと考えられます。

**運用者がやること**

- [ ] 資産管理ツールなどで、32bit 版 Windows の端末が残っていないか確認する
- [ ] 残っている場合は、64bit 版への入れ替えや、ZDX の監視対象から外す計画を立てる

### Cloud Path プローブの TTL を 64 に引き上げ

**何が変わったか**
Cloud Path プローブのうち、**resilient** と **strict** のプローブで、**TTL を 64 に引き上げ**ました。経路上のホップ（通信が経由するルーターなど）が **30を超える**環境で、プローブが途中で途切れてしまうのを防ぐためです。

**どんな機能か**
Cloud Path プローブは、端末から宛先までの経路をホップごとに測り、どこで遅延やパケットロスが起きているかを見える化する機能です（11月11日の ZDX 入門の記事で解説）。
**TTL（Time To Live）**は、パケットが通過できるホップ数の上限です。ホップを1つ通るたびに1ずつ減り、0になるとそのパケットは捨てられます。そのため、TTL より多くのホップがある経路では、プローブが宛先に届く前に途切れてしまいます。

**対象となる人・設定**
海外の拠点やクラウドなど、**経路が長い宛先**を ZDX で監視している組織です。これまで Cloud Path の表示が途中で途切れていた場合は、この変更で改善する可能性があります。

### Remediation の実行前に PowerShell の実行ポリシーを確認

**何が変わったか**
Remediation の設定に、診断・修復スクリプトを実行する前に **Windows PowerShell の実行ポリシー（Execution Policy）を確認する**ための制御が加わりました。

**どんな機能か**
ZDX の **Remediation** は、問題が利用者から報告される前に、管理者がスクリプトを端末に遠隔で実行して、先回りで解決するための機能です。公式ドキュメントでは、端末側の前提条件として「PowerShell の実行ポリシーが制限されていないこと」が挙げられています。
今回の変更で、実行前にこの条件を確認できるため、条件を満たさない端末でスクリプトが失敗する状況を把握しやすくなると考えられます。

**運用者がやること**

- [ ] Remediation を使っている場合、新しい設定項目を確認し、実行ポリシーの確認を有効にするか決める
- [ ] グループポリシーなどで PowerShell の実行ポリシーを制限している端末がないか確認する

### そのほかの変更

- **外部のフォワードプロキシへの直接接続**：ZDX のクライアントの経路設定を、管理者が設定できるようになりました。自社で外部のプロキシを経由している環境での測定に関係します
- **Extranet アプリケーションへの対応**：Client Connector と ZDX の Cloud Path が、Extranet アプリケーションに対応しました（Extranet 機能の詳細は公式情報で要確認）
- **Multi-Connect SME での Traceroute**：Client Connector の Multi-Connect SME 機能で Traceroute に対応し、Cloud Path の表示とホップごとの遅延が見られるようになりました
- **セキュリティの強化**：Client Connector と ZDX モジュールのセキュリティが強化されました（詳細は原文に記載なし）

## iOS 版 ZDX モジュール 5.0.0

### 省電力化：測定を止める条件が増えた

**何が変わったか**
iOS 版では、バッテリーを長持ちさせるため、次の場合に ZDX の動作やプローブを止めるようになりました。

**対象となる人・設定**
iOS 端末で ZDX を使っている組織です。11月13日の ZCC の記事で取り上げた Android 版（10分間操作がないと ZDX を一時停止）と同じく、モバイル端末では「測定しない時間」が増えています。

**運用者がやること**

- [ ] iOS 端末の ZDX のデータに空白があっても、ロック中や電池残量の少ない時間ではないかを確認してから、障害かどうかを判断する

### デバイスイベントへの対応、画面の簡素化

iOS 版でも **ZDX のデバイスイベント**に対応しました。公式ドキュメントによると、デバイスイベントは、システムやソフトウェアのクラッシュなど、利用者と端末に影響する出来事を集計して見せる機能です（Advanced のサブスクリプションが必要）。
あわせて、Client Connector アプリの操作をわかりやすくする改善も入っています。

## まとめ

- Windows 版 ZDX モジュールで **32bit（x86）版 Windows のサポートが終了**。端末の棚卸しを優先する
- Cloud Path プローブの **TTL が 64** になり、ホップ数の多い経路でも宛先まで測れるようになった
- iOS 版は**ロック中・ネットワーク断・残量15%未満で測定を止める**。データの空白を障害と取り違えないよう注意する

今週の製品別アップデート（ZCC・ZIA・ZPA・ZDX）は、これで全部です。次は11月20日（金）に、11/13〜11/19 の分をまとめます。変更の全文は、公式の [ZDX Module Release Summary (2026)](https://help.zscaler.com/zscaler-client-connector/zdx-module-release-summary-2026) で確認してください。
