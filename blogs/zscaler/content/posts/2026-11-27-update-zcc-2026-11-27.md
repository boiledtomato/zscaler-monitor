11月20日〜26日に公開された Zscaler Client Connector（ZCC）の更新は、**iOS 版 5.0.3 の1件**でした。
修正は2つです。1つは、新しい UI で **ZPA の再認証に失敗する**問題、もう1つは、**ZIA と ZPA は接続済みなのに Wi-Fi が使えない**問題です。どちらも、利用者から「つながらない」という問い合わせになりやすい症状です。iOS 版 5.0 は一般提供から4週続けて修正が出ており、その流れもあわせて整理します。

Windows・macOS・Linux・Android・ChromeOS は、この期間に新しいバージョンは出ていません。

## 修正1：NameID にドメインがないと ZPA の再認証に失敗する

### 何が変わったか

**再設計された（新しい）UI** で、IdP が返す **NameID にドメインが含まれていない**場合に、**ZPA（Private Access）の再認証に失敗する**問題が直りました。

### どんな機能か

ZPA では、利用者は会社の **IdP**（Microsoft Entra ID や Okta などの認証基盤）で、**SAML** という仕組みを使って認証します。IdP は認証が終わると、「この利用者は誰か」を **NameID** という識別子で ZPA に伝えます（一般的な説明です）。

NameID の形は IdP の設定によって異なり、たとえば次のような形があります。

- ドメインあり：`user@example.co.jp`
- ドメインなし：`user`

ZPA は一定の時間がたつと、利用者に**再認証**（もう一度ログインすること）を求めます。今回の不具合は、新しい UI でこの再認証を行うとき、NameID が**ドメインなしの形**だと失敗してしまう、というものでした。

### 対象となる人・設定

- iOS 版 5.0 系で**新しい UI** を使っている
- IdP が ZPA に返す **NameID にドメインが含まれていない**

11月20日の記事で紹介したとおり、Ownership ポスチャを使うテナントでは、Zscaler が iOS の新しい UI の既定を一時的に無効にしていました。新しい UI を使っているかどうかは、管理画面の **Infrastructure > Client Connector > App Profile & Platform Settings > iOS > Platform Settings** にある「Default to Modern Client UI Experience」の設定で確認できます。

### 運用者がやること

- [ ] IdP の SAML の設定で、ZPA に返している NameID の形（ドメインの有無）を確認する
- [ ] 該当する場合、iOS 端末の Client Connector を 5.0.3 へ更新する
- [ ] 「しばらく使っていると社内アプリにつながらなくなる」という iOS の利用者からの問い合わせがあれば、この問題を疑う

### NameID の形を確かめるには

NameID の形は、IdP 側の SAML アプリの設定で決まります。SAML の標準では、NameID の形式（NameID Format）として、メールアドレス形式（emailAddress）、特に指定しない形式（unspecified）、利用者ごとに固定の識別子を使う形式（persistent）などが定められています（SAML の一般的な説明です）。
「unspecified」や「persistent」の場合、`user` のようなドメインのない値が返ることがあります。確認の手順は、次のように考えられます（個人の整理です）。

1. IdP の管理画面で、ZPA 用に作った SAML アプリの設定を開く
2. NameID（Name identifier）に、どの属性（メールアドレス、ユーザー名など）を使っているか確認する
3. その属性の実際の値に、`@` 以降のドメインが含まれているか、テスト用の利用者で確かめる

ZPA の SAML 属性や利用者の識別に関わる設定は、組織によって作り方が異なります。設定を変える前に、ZPA のポリシーで使っている条件への影響を必ず確認しましょう。

## 修正2：ZIA・ZPA は接続済みなのに Wi-Fi が使えない

### 何が変わったか

Client Connector **5.0 以降**で、アプリの画面では **ZIA（Internet & SaaS）と ZPA（Private Access）が接続済み**と表示されているのに、**Wi-Fi が使えない**問題が直りました。

### どんな機能か

Client Connector は、端末の通信を ZIA や ZPA へ送る**トンネル**を張ります。画面に「接続済み」と表示されていても、端末の通信そのものが Wi-Fi に出られなければ、利用者からはインターネットも社内アプリも使えません。
「Client Connector は正常なのに Wi-Fi がつながらない」という症状は、利用者にも管理者にも原因が分かりにくく、切り分けに時間がかかりがちです（症状の具体的な起き方は原文に記載なし）。

### 対象となる人・設定

原文の条件は「**5.0 以降の Client Connector を使っている利用者**」だけです。どんな Wi-Fi や設定で起きるかは書かれていません。

### 運用者がやること

- [ ] iOS 端末の Client Connector を 5.0.3 へ更新する
- [ ] ヘルプデスク向けに、「接続済みと表示されているのに Wi-Fi が使えない」場合は、まず Client Connector のバージョンを確認する手順を共有する

## 修正が続くときの配り方

メジャーバージョン（今回は 5.0）の直後は、今回のように修正版が短い間隔で出ることがあります。iOS 版は App Store で配られるため、MDM で管理している組織と、利用者に任せている組織とで、更新の進み方が変わります（個人の整理です）。

- **MDM で管理している場合**：配るバージョンを決めて、まず一部の端末で試してから全体に広げる
- **利用者に任せている場合**：古いバージョンが残りやすい。Client Connector の管理画面で、端末ごとのバージョンを定期的に確認する
- **どちらの場合も**：既知の問題が直ったバージョン（今週なら 5.0.3）を「最低限このバージョン以上」として社内に案内しておく

## まとめ

- 今週の ZCC は iOS 版 5.0.3 の1件。新しい UI で NameID にドメインがないと ZPA の再認証に失敗する問題と、5.0 以降で Wi-Fi が使えない問題を修正
- どちらも「つながらない」という問い合わせになりやすい症状。iOS 端末は 5.0.3 への更新を確認したい
- iOS 版 5.0 系は、11/10 の一般提供から4週続けて修正が出ている

明日（土曜）は、同じ期間の **ZIA** のアップデートを取り上げます。今週は ZDX の更新がなかったため、シリーズは ZCC → ZIA → ZPA の3回です。
