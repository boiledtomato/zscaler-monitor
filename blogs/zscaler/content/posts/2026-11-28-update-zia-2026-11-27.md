11月20日〜26日に公開された ZIA（Zscaler Internet Access）の変更は**7件**で、すべてが**データ保護と SaaS セキュリティ**に関わるものでした。
目を引くのは、生成AIの **Claude** に保存されたデータへの **DLP・マルウェアスキャン**の対応です。ほかにも、画像の中の **QR コード**を見つける DLP 辞書や、**ソースコード**のファイル種別の追加など、「どんなデータが外に出ていくか」を見る力が広がっています。

なお、ファイル種別と DLP 辞書は、インライン型だけでなく、エンドポイント DLP、送信メール、保存データのスキャン（Data at Rest Scanning）にも使われます。

## Claude の DLP・マルウェアスキャン

### 何が変わったか

生成AIのカテゴリ（**Gen AI**）で、**Claude** に対する **DLP** と**マルウェアスキャン**のポリシーを作れるようになりました。

### どんな機能か

これは API 型（アウトオブバンド）の機能で、Claude の中に**保存されたデータ**を調べます。手順は次のとおりです。

1. **Data Security > DSPM > SaaS Application Tenants** で、Claude を**テナントとして登録**する
2. **Data Security > DSPM > SaaS DLP > Gen AI** で、Claude 向けの **DLP ポリシー**を作る
3. **Data Security > DSPM > Malware Scanning > Gen AI** で、Claude 向けの**マルウェアスキャンのポリシー**を作る

11月24日の記事で紹介した ZDX の定義済みアプリへの Claude の追加が「**体感品質**」の監視だったのに対し、今回は「**データ**」の保護です。

### 対象となる人・設定

業務で Claude を使い、SaaS Security（API 型）を契約している組織。どの Claude のプラン（法人向けなど）が対象かは、原文に記載がありません。

### 運用者がやること

- [ ] 社内で Claude を使っている部署と、そのテナント（組織のアカウント）を把握する
- [ ] テナントを登録し、まず「報告だけ」の DLP ポリシーで、どんなデータが保存されているかを確かめる
- [ ] 見つかった内容をもとに、対応（削除・隔離など）の方針を決める

## ファイル種別の追加：ソースコードなど

### 何が変わったか

**ファイル種別制御**と **DLP**（インライン、エンドポイント、送信メール、保存データのスキャン）で使える定義済みのファイル種別に、次のようなものが加わりました。

| 分類（個人の整理） | ファイル種別 |
|---|---|
| Web・アプリのソースコード | TypeScript（.ts）、TypeScript+JSX（.tsx）、PHP（.php）、ASP.NET（.asp、.aspx など）、Java Server Pages（.jsp、.jspf）、Java Server Faces（.jsf） |
| JVM 系のソースコード | Kotlin（.kt、.kts）、Apache Groovy（.groovy など） |
| SAP の ABAP | ABAP ソースコード（.abap）、ABAP CDS（.acds）、ABAP 振る舞い定義（.abdl） |
| そのほか | C++（.cxx）、クラスモジュール（.cls）、R スクリプト（.r）、電子名刺（.vcf） |

### どんな機能か・対象となる人

**ファイル種別制御**は、ファイルの種類によって、アップロードやダウンロードを許可・ブロックする機能です。今回の追加で、**ソースコードの持ち出し**をファイル種別で見分けやすくなります。電子名刺（.vcf）は、連絡先の一覧の持ち出しにも関わります。
対象は、ファイル種別制御や DLP でファイル種別を条件にしている組織、とくにソフトウェアを開発している組織や、SAP を使っている組織です。

### 運用者がやること

- [ ] 開発部門以外からのソースコードのアップロードをどう扱うか、方針を決める
- [ ] 新しいファイル種別をルールに加える前に、まず「報告だけ」で影響を確かめる

## DLP の QR コード辞書

DLP に **QR コード**の定義済み辞書が加わりました。**JPEG や PNG** などの対応する画像ファイルに含まれる、**QR コードの画像**を検出します。
QR コードには URL や文字の情報を埋め込めるため、どんな場面で検出したいかは組織によって異なります。まずは、どのくらいのファイルが当たるかを確かめてから、ポリシーに使うかを決めるのがよいでしょう（個人の整理です）。

## OneDrive・SharePoint の MIP ラベルの上書き

**MIP ラベル**（Microsoft Purview Information Protection の秘密度ラベル）は、ファイルに「社外秘」などの区分を付ける Microsoft の仕組みです。
**Metered APIs Labeling** のオプションで OneDrive・SharePoint のテナントを登録すると、ポリシーの動作「**Apply MIP Label (Metered API)**」で、Word・Excel・PDF のファイルに新しいラベルを付けたり、既存のラベルを**上位・下位のラベルに上書き**したりできるようになります。
**Zscaler Defined** のコネクタで登録しているテナントは、コネクタの種類を **Custom** に変えて、テナントを再検証する必要があります。

## そのほかの変更

- **新しい定義済み DLP 辞書（11件）**：アルゼンチンの国民身分証番号（DNI）、チェコ・ラトビア・ルーマニア・ベネズエラの個人識別番号、ケニアのパスポート番号・納税者番号・国民識別番号、ポルトガルの社会保障番号、キプロスの納税者番号、アジアの電話番号
- **Advanced SSPM の Zoho 対応**：テナントを登録するときに「SSPM Scan」のチェックを入れると、Zoho のテナントで Advanced SSPM のスキャンを使える（Advanced SSPM を有効にしているテナントのみ）
- **SaaS Security Insights Logs の「Is Deleted」フィルター**：削除（Delete）の操作に関わる記録だけを絞り込める。ファイルの大量削除などを調べるときに使える

## まとめ

- 今週の ZIA は7件すべてがデータ保護。Claude に保存されたデータの DLP・マルウェアスキャンに対応した
- QR コードの DLP 辞書、ソースコードなどのファイル種別、各国の ID の DLP 辞書が加わり、「何が出ていくか」を見分ける力が広がった
- OneDrive・SharePoint の MIP ラベルの上書き、Advanced SSPM の Zoho 対応、Is Deleted フィルターも追加。新しい条件は「報告だけ」で試してから使いたい
