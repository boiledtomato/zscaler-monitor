# 共通の執筆ルール（両ブログ）

各ブログの `WRITING_GUIDE.md` とあわせて必ず読むこと。

## 出力形式

`blogs/<blog>/content/posts/YYYY-MM-DD-<topic_id>.md` に、次のフロントマター付き Markdown を1本書く。

```markdown
---
title: "記事タイトル（32文字前後、検索されそうな語を前に）"
date: 2026-11-03
tags: [<ナビ用タグ>, 他のタグ...]   # 先頭は各ブログのガイドで指定されたナビ用タグ
summary: "検索結果に出る120文字前後の要約"
topic_id: <ブリーフで指定された id>
image: "https://..."          # 任意。パブリックドメイン画像のみ
image_credit: "..."           # image がある場合は必須
sources:
  - "https://..."
learning:
  - "この記事で押さえるべきポイント（3つ）"
quiz:
  - q: "確認問題（2〜3問）"
    a: "答えと短い解説"
---

本文（Markdown）
```

## 本文の構成

1. 導入（2〜3文）：誰の、どんな疑問に答える記事か
2. 本題：`##` 見出しで3〜5セクション。表・箇条書きを適度に使う
3. まとめ：3行程度
4. 学習ポイントとクイズはフロントマターに書く（本文に重複させない。サイト側で自動表示）

分量の目安：本文 2,500〜4,000 文字。

## 品質ルール

- 事実と推測を分ける。仕様・数値・日付・制作年などは、ブリーフの資料か広く確立した知識に限る。
  確信が持てない細部は書かないか「公式情報で要確認」と明記する。
- 出典を必ず `sources` に入れる。公式文書の丸写しはしない（引用は短く「」で）。
- 企業・美術館の公式を装わない。「個人の学習ノート」の立場で書く。
- 同じ topic_id の記事を二度書かない（ビルド時にチェックされる）。
- 誇張した煽り（「絶対」「最強」）や根拠のない比較はしない。
- もう一方のブログの話題は書かない（Zscaler ブログに美術、美術ブログに IT の話を混ぜない）。
